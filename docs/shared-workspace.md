# Shared GUS workspace, release deletion, and live refresh

The user requested that all authenticated GUS organization users see the same dashboard backend, can delete releases, and see updates made either in GUS or the dashboard. The current per-user ContentVersion journal does not explicitly share its files. This change grants organization-wide Viewer links only to this app's journal files, so each signed-in user can read the same immutable history and append their own changes. This explicitly makes cached epic fields, comments, and drafts readable by every internal GUS user, including users whose native epic-record visibility may be narrower. It does not change native permissions on GUS epic/work-item records or create anonymous/public-internet access. Direct reads/writes continue to use the signed-in user’s native permissions.

Existing app-only history must be migrated to the same organization sharing scope. New writes fail if organization sharing cannot be established. Commit markers are activated only after their chunks and commit file are shared, preventing the owner from seeing a private committed update that others cannot read. No other application's files are touched.

Release deletion appends a shared tombstone after validating its current revision and explicit confirmation. It never deletes GUS epics, monthly comments, or shared epic drafts. Deleted releases disappear for all users and are rejected by mutation endpoints. Duplicate saved aliases for the same displayed scope are also retired together, so a hidden duplicate cannot reappear after deleting its visible release.

The open dashboard refreshes its shared release/draft state regularly and when focus returns. Current GUS fields/comments are read into the displayed epics on a bounded per-epic refresh, preserving pending drafts and stopping on conflicts. An editor keeps the month baseline it opened with, even if an already-running Fetch completes while the editor is open. A displayed last-refresh status distinguishes cached state from fresh GUS data. The UI does not claim real-time push or continue a browser task after its tab closes.

Existing monthly-save safeguards remain: the selected month only, durable draft first, remote reread/conflict check, and readback verification. GUS reads/writes still run under each signed-in user's permissions. Metadata such as assignee, sprint, points and selected filters use compact chips. Table metadata columns use measured headers and values rather than a fixed 190px budget.

Salesforce rejects `InternalUsers` visibility for Organization-linked ContentDocumentLink records. These app-only links therefore use `LinkedEntityId = current Organization.Id`, `ShareType = V`, and `Visibility = AllUsers`, verified exactly. The scope is authenticated users in that GUS organization, potentially including any external/community accounts present there; it is not a public internet link and creates no ContentDistribution. This follows the user’s request for all users to share the dashboard backend.
